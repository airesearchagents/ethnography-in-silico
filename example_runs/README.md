# Example runs

Records of four prototype runs (test runs, not study results; each run is one complete simulated meeting and debrief), all simulating one firm in a dynamic industry with a novel product, on `gemini-3.1-pro-preview` (an early release of a Google language model, a program trained on vast amounts of text to write likely continuations of the text it receives). **All text is synthetic: generated by language-model agents (language models given a name, a role and instructions), and never the view or decision of a real person or firm.** The table describes the prompts (the text sent to a model) behind each run.

| Folder | Prompts |
|---|---|
| `run_A/` | Before steering wording (leading agents toward what a study hopes to find) was removed (`DECISIONS.md` §35, a numbered entry). Panelists (role agents questioned in the debrief) were shown the research question |
| `run_B/` | Neutral |
| `run_C/` | Neutral, with the researcher free to follow what it finds |
| `run_D/` | Neutral, with questions exploring the research question, and grounded in one firm's documents (given them to cite; unrelated to grounded theory). **Source text removed** |

`short_check/` is not one of the four. It checks the current code (`DECISIONS.md` §52): a live (on a real model) grounded run through every phase (numbered stage of a run), capped at 3 actions (moves by a role) per role and 3 debrief exchanges (a researcher question and its replies), with source text removed. It is a check on wiring (how the parts connect) and cost, not data.

Its manifest names a commit from our private working copy, which is not in the public history; [`short_check/README.md`](short_check/README.md) explains this and the one file hash that differs. The manifest does not yet record deliberation settings or the researcher agent's model: `deliberation_config` is empty and `models_used` lists only the six roles. The run's `00_meta.json` records its caps and the researcher agent's provider.

`provenance/` holds, for each run, a report on where its words first appeared, from `python -m analysis.provenance`. `prompts_as_run/` holds the prompts each run used, so you can read and compare them.

**Run D** comes from `python -m analysis.redact_run`, because source documents may be under copyright. Each retrieved passage keeps its document, chunk (the piece cut from the document for searching), score and a hash (a short fingerprint computed from the text), but not its text. Each cited quote is replaced by a hash and word count, and any run of six or more words matching a source document is replaced by `[source text removed]`, so some sentences have gaps. The source documents can be made available privately on request, through the editors, for review purposes only and as copyright permits.

Optional scoring output is left out of these folders.

`panel_probe/` holds a test of whether different roles are different voices, with its own explanation.

These records come from earlier versions of the code, and `../DECISIONS.md` §50 and §52 list what has changed. In particular, a role invited to build on another's answer was not shown it, and in run D each role saw only the first 1,200 characters of a retrieved passage. In run D's retrieval log, `chunk_id` is a passage's rank within one retrieval. Runs A to D also predate `manifest.json` and `08_usage/`, and their `00_meta.json` names no code version, so use `prompts_as_run/` to see what they were told.

[`../docs/LEARNINGS.md`](../docs/LEARNINGS.md) explains what these runs taught us.

## Read one run: run D

Run D has the fullest records. Run C has the same files without field notes and `07_rag/`, and with no text removed. In `run_D/`, read in this order:

1. `00_meta.json`: the setup. Under `errors`, `panel_answers_lost` means failed model calls lost two debrief answers; the transcript marks both.
2. `01_deliberation/interaction_log.md`: the public discussion.
3. `06_private_channel/`: private notes and drafts.
4. `02_strategy_documents/`: each role's strategy document.
5. `03_researcher/`: the researcher agent's reading, not the team's.
6. `04_interview/transcript.md`: the debrief. An "area" is a debrief topic, from `protocols/ethnographic_protocol.yaml` or the study's `debriefing_overlay.yaml`; "Anchored on" is what the question refers back to.
7. `07_rag/`: passages retrieved, with their text removed.

The log shows 31 entries, but the run made 210 model calls: notes, drafts, strategy documents and debrief replies are calls too.

When coding, ask who supplied each passage and check past claims against the log ([`LEARNINGS.md`](../docs/LEARNINGS.md) L3, L4).
